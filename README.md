# 开物 · 工业设备知识中枢 v0.1

> 基于大模型与工业垂直知识库的设备故障诊断与知识中枢（OPC-2026-0207 参赛作品原型）

**名字由来**：取自宋应星《天工开物》与《易经》"开物成务"。四百年前，《天工开物》把散落的
工农业技术整理成可查证的典籍；今天，开物把散落在设备手册、维修工单、点检表里的工业知识
整理成可检索、可推理、可溯源的数字资产——让工业知识"开物"，即被激活、被使用、被传承。

## 一句话

通用大模型答"网络通不通"，开物答"这台设备为什么停、按哪本手册第几页修、先修哪个"。
它把设备手册、维修工单、点检表里的工业知识变成可检索、可推理、可溯源的资产，
每条结论都能追到**手册页码**或**工单编号**，不编造、可核验。

## 30 秒跑起来

```powershell
# Windows（本机演示用）
pip install fastapi uvicorn pymupdf
python make_manuals.py    # 生成 3 份演示手册 PDF + 3 份维修工单
python app.py             # 浏览器打开 http://127.0.0.1:8000
```

```bash
# Linux / 沙箱
pip3 install fastapi uvicorn pymupdf
python3 make_manuals.py && python3 app.py
```

首次启动自动解析 PDF、构建页码级索引与知识图谱，无需任何 API Key。
接入 DeepSeek 可增强自然语言问答质量（见 app.py，OpenAI 兼容接口即可）。

## 技术方案要点（可直接写进作品说明文档）

1. **页码级解析**：PyMuPDF 逐页提取，按编号章节切分，chunk 携带 `文档/页码/章节`，
   证据可回指；表格按结构化行保留。
2. **混合召回**：中文按字符二元组切分（无需分词词典），BM25 关键词召回 +
   文档多样性裁剪（同一文档最多 2 条证据，防证据同源）；
   平台层可叠加 BGE-M3 向量召回与 RRF 融合（见 NetResearchAI）。
3. **证据门控（抗幻觉）**：检索最高分低于阈值时明确拒答；
   机理与处置仅从 Top-3 证据全文提取，不做证据外推断。
4. **知识图谱**：规则抽取（可审计、可复现），每条关系携带
   `文档 ID / 页码 / 证据原文 / 置信度 / 抽取器版本`；
   现象→根因→措施 三元组通过同段共现建立，权重随共现次数增长。
5. **停机影响分级**：P0 安全链 / P1 主工艺链 / P2 局部异常 / P3 隐患，
   诊断结论必须回答"先修哪个"而不只是"哪里坏了"。
6. **只读安全边界**：巡检探测只读、低频、单连接、用后释放，禁止写 PLC。

## 与平台层的关系

本项目是**领域层实现**（知识库、实体抽取、诊断逻辑、工业界面）；
平台层工程能力（混合检索工程化、Agent 编排、租约/fencing/幂等、OCR）
复用 NetResearchAI 的成熟实现。两仓关系与接入方式见参赛方案文档。
