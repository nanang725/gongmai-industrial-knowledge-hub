# 工业网络故障模式库

> 每条故障模式包含：现象特征、作用机理、验证方法、处置步骤、常见误判。
> 检索方式：以巡检采集到的"现象文本"为查询，匹配本条目的现象特征段落。

## 故障模式 F01：PLC 端口可连但业务读写超时

**现象特征**：102 或 502 端口 TCP 三次握手成功，应用层读写出错或超时；ping 正常、丢包 0%；同一 PLC 的触摸屏显示正常。

**作用机理**：TCP 可达只代表协议栈在线，不代表 PLC 的通讯资源可用。常见成因按概率排序：并发连接数达到上限、机架/槽号配置错误、从站站号错误、寄存器地址越界、PLC 处于 STOP 或处于下载模式。

**验证方法**：先看 PLC 前面板 RUN/STOP 与 ERROR 灯；再用单个客户端独占连接测试，若独占可通、并发不通，则确认是连接资源耗尽；最后核对机架槽号与站号配置。

**处置步骤**：1）关闭多余的上位机/巡检客户端连接；2）确认 PLC 运行模式；3）核对机架槽号、站号、寄存器映射表；4）必要时重启 PLC 通讯服务（需生产许可）。

**常见误判**：把"端口通"当作"服务正常"，直接判定网络无故障，导致故障在应用层反复出现。

## 故障模式 F02：同交换机下多台设备同时失联

**现象特征**：一批设备集中失联，且这些设备挂在同一台工业交换机下；跨交换机的设备访问正常；ping 表现为全部超时或高丢包。

**作用机理**：故障点在 L2。可能是交换机某个端口组故障、VLAN 划分被改动、环网冗余切换失败、STP 收敛风暴、或该交换机上行链路中断。

**验证方法**：登录交换机查看端口 up/down 与 CRC 错误计数；查看 MAC 地址表是否还在学习；查看环网冗余状态与 STP 拓扑变更计数。

**处置步骤**：1）确认上行链路光/电口状态与光功率；2）检查 VLAN 配置是否被变更；3）查看环网是否处于切换态；4）替换疑似故障端口做交叉验证。

**常见误判**：逐台去ping设备，得出"多台设备同时坏了"的错误结论，忽略共同的上游节点。

## 故障模式 F03：DNS 解析异常但网关可达

**现象特征**：默认网关 ping 通、丢包 0%；域名类目标解析失败或解析到异常地址；直接用 IP 访问正常。

**作用机理**：本机或现场 DNS 服务器不可用、DNS 服务器地址被策略改写、域名劫持、或终端处于代理/VPN 环境导致流量被虚拟网卡接管。

**验证方法**：分别用现场 DNS 与公共 DNS 解析同一域名做对比；查看本机 DNS 配置来源（DHCP 下发还是静态）；检查是否存在 TUN/虚拟网卡接管默认路由。

**处置步骤**：1）恢复正确 DNS 服务器地址；2）清除本地 DNS 缓存；3）排查终端侧代理软件；4）生产网内应统一由现场 DNS 提供解析，不允许终端自定义。

**常见误判**：把 DNS 故障当成"断网"，去查物理链路，浪费时间。

## 故障模式 F04：跨网段不通而同网段正常

**现象特征**：同网段设备互 ping 正常；跨网段目标全部超时；tracert 在网关处中断。

**作用机理**：网关未配置回程路由、子网掩码错误导致误判同网段、NAT/ACL 拦截、或三层交换机路由表缺失。

**验证方法**：核对双方 IP 与掩码，确认是否真的同网段；在网关上看路由表与 ACL 命中计数；用 tracert 定位中断跳。

**处置步骤**：1）修正掩码；2）补回程路由；3）放行对应 ACL；4）确认工业网段与办公网段之间的隔离策略是有意为之。

## 故障模式 F05：间歇性丢包与周期性通讯中断

**现象特征**：大部分时间正常，特定时段（如大型设备启停、变频器运行、行车经过）出现丢包或通讯中断；重试后自行恢复。

**作用机理**：电磁干扰（变频器、伺服、大功率启停）、屏蔽层接地不良、网线与动力线同槽敷设、交换机温度过高降速、或环网存在短暂环路引发广播风暴。

**验证方法**：看丢包是否与设备启停时刻强相关；查交换机 CRC/对齐错误计数是否增长；测温；检查屏蔽层单端接地是否符合规范。

**处置步骤**：1）网线与动力线分槽、保持间距；2）完善屏蔽与接地；3）更换工业级屏蔽线；4）改善柜内散热；5）排查环路。

**常见误判**：只测一次正常就结案，忽略间歇性特征，导致故障反复。

## 故障模式 F06：广播风暴导致全网变慢

**现象特征**：全网延迟整体升高但不断线；交换机指示灯高频闪烁；CPU 利用率飙升。

**作用机理**：环网未启用冗余协议却接了环、或双上行未做聚合，形成二层环路；或某设备网卡故障持续发广播。

**验证方法**：查看交换机 CPU 与广播包速率；逐段拔线定位环路点；检查冗余协议配置。

**处置步骤**：1）断开疑似环路；2）启用正确的环网冗余协议并确认角色；3）对故障网卡设备下线；4）配置广播风暴抑制阈值。

## 故障模式 F07：工业协议实时通道异常但 IP 层正常

**现象特征**：ping 通、TCP 端口通，但 PROFINET/EtherCAT 从站掉站、伺服报警、I/O 不同步。

**作用机理**：实时协议走二层，不依赖 IP；故障多源于交换机不支持所需实时特性（如未开启优先级、无透明时钟）、拓扑层级过深、或线缆质量导致误码。

**验证方法**：看主站诊断缓冲区与从站在线计数；看交换机是否支持并启用相关实时特性；测线缆误码。

**处置步骤**：1）检查交换机型号与实时特性配置；2）减少级联层级；3）更换线缆与接头；4）核对拓扑与组态是否一致。

**常见误判**：用 IP 层工具（ping/端口扫描）判定"网络正常"，把问题推给设备厂家。

## 故障模式 F08：时钟不同步导致事件记录错乱

**现象特征**：各设备事件时间戳互相矛盾；SOE 记录顺序与现场实际不符；跨系统日志无法对齐。

**作用机理**：NTP 服务器不可达、各设备独立走本地时钟、PTP 主时钟未指定或精度不足。

**验证方法**：抓取各设备当前时间做偏差比对；检查 NTP/PTP 配置与可达性。

**处置步骤**：1）统一时钟源并确认可达；2）对运动控制类设备启用 PTP；3）保留时钟偏差监控项作为巡检常态指标。
